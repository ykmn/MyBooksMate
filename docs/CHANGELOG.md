## 2026-06-24 — Calibre-плагин: найден настоящий баг поиска — query приходит как bytes (v1.0.003)
- После включения чекбокса магазина в "Получить книги" поиск по полю "Автор" всё равно возвращал "Нет совпадений". Изучил исходники Calibre (`calibre/gui2/store/search/search.py`, `do_search`/`clean_query` через `gh search code` + `WebFetch` на raw.githubusercontent.com): диалог сам собирает запрос из полей Название/Автор/Ключевые слова (`title2:"~..."`, `author2:"..."`, конкатенация), затем чистит его через `clean_query()` — который **лишает запрос регистра и возвращает `bytes`** (`return query.encode('utf-8')'), а не `str`.
- Это и был баг: `store.py`'s `search()` передавал этот `bytes`-объект прямиком в `api.search_books()`, где `json.dumps({'variables': {'search': query, ...}})` падал с необработанным `TypeError: Object of type bytes is not JSON serializable` — исключение происходило вне `try/except` (до того, как тело запроса попадало в HTTP-вызов), Calibre тихо проглатывал ошибку в пуле потоков поиска и показывал "Нет совпадений" без какой-либо диагностики.
- Исправлено в `store.py`: `search()` теперь декодирует `query` в `str`, если это `bytes`, перед вызовом `api.search_books()`.
- Проверено через `calibre-debug.exe`, эмулируя точный формат, который шлёт Calibre (lowercase + UTF-8 bytes, как после `clean_query`) — теперь возвращает корректные результаты.
- Версия плагина увеличена до `(1, 0, 3)`.

## 2026-06-24 — Calibre-плагин: поиск переведён на реальный GraphQL-эндпоинт сайта (v1.0.001)
- Скрейпинг `books.yandex.ru/search` из первой версии плагина оказался полностью нерелевантным: страница — Next.js-приложение, рендерящее результаты поиска через client-side GraphQL, а статический HTML содержит только не зависящие от запроса "рекомендованные" книги (отсюда жалоба пользователя: "Пелевин" находил книгу Данилкина, "Пушкин" — вообще ничего, "Полдень" — не по теме).
- Реальный эндпоинт найден через DevTools пользователя (`Copy as cURL` на запросах `Search`/`SearchTabs`): `POST https://books.yandex.ru/node-api/p-graphql/`. Сервер использует allow-list GraphQL-запросов (`{"errors":[{"message":"Whitelist: query not found"}]}` на любой текст запроса, отличающийся от зарегистрированного хотя бы пробелом) — поэтому `api.py.SEARCH_QUERY` хранит точный текст запроса (включая все GraphQL-фрагменты), скопированный из реального запроса браузера, и его нельзя переформатировать.
- `search_books()` переписан: POST на `/node-api/p-graphql/` с `operationName: "Search"`, variables `{search, cursor: "", noMisspell: false}`, фильтрует `page[]` по `__typename == "TextBook"`. Авторизация для самого поиска не требуется (работает и без `auth-token`/куки сессии) — нужна только для скачивания контента.
- Проверено на реальных запросах "Пелевин"/"Пушкин"/"Полдень" через `actual_plugin.search()` — все результаты релевантны (книги нужного автора/с нужным словом в названии).
- Версия плагина увеличена до `(1, 0, 1)` согласно правилу версионирования в `CLAUDE.md`.

## 2026-06-23 — Предупреждение о повторном скачивании, реальный фикс обложки EPUB
- Найден и исправлен баг в `fix_epub_cover` (`RUBookmatedownloader.py`): фактическая причина, по которой обложка не восстанавливалась даже после первой попытки фикса — в EPUB от Bookmate отсутствующий файл изображения **не помечен** как обложка через `meta name="cover"` или `properties="cover-image"` (вообще никакой явной маркировки cover нет), поэтому старый код не находил `cover_href` и ничего не восстанавливал. Кроме того, в логике fallback была ошибка: `None not in existing_names` всегда `True`, из-за чего код заходил в неверную ветку и пропускал восстановление. Переписана на `_find_epub_image_items`: теперь собираются все image-манифесты, и если явный cover не определён, но отсутствует ровно один image-файл — он считается обложкой и восстанавливается. Воспроизвёл точную ошибку "There is no item named 'OEBPS/lp28mbue93c.jpeg' in the archive" на синтетическом EPUB без явной маркировки cover и подтвердил, что после фикса `ebooklib` читает файл без ошибок и обложка восстановлена.
- Добавлена проверка перед скачиванием: если книга/комикс уже скачаны, показывается диалог "Скачать заново" / "Пропустить" вместо тихого пропуска (`RUBookmatedownloader.find_existing_file`, `mybooksmate/downloader.py`, `mybooksmate/main_window.py`). При выборе "Скачать заново" в `download_book`/`download_comicbook` передаётся `force=True`, заставляя перезаписать файл.

## 2026-06-23 — Фикс: сессия логина на books.yandex.ru сбрасывалась при запуске из release/

Это не зависит от того, каким интерпретатором и из какой папки запущено приложение.
- `webengine_profile/` добавлен в `.gitignore`.
